0.3.0 adds custom ordering and editable section pages, and tightens how publishes and file writes stay attached to their original site.

## New

- **Editable section landing pages:** `_index.*` pages now appear in Content with a section label and open in Preview, Raw and the structured front matter editor. Leaf-bundle `index.*` files remain regular pages.
- **Custom order:** arrange pages within a section by dragging or using row controls. HugoKit updates `weight` only on changed pages and records the operation as one snapshot. If validation or a write fails, no partial order is kept.
- **Front matter weight editing:** the structured editor now shows an existing `weight` field without adding it to unweighted pages.
- **Existing tags and categories:** the `+` buttons show values already used by the site. The picker supports search, hides selected values and still accepts manual entry.

## Improved

- **Persistent build trends:** each site now keeps its latest 50 successful and failed builds across app launches. Existing sites start with an empty history.
- **External file changes:** Content and Configuration now stop before saving when another editor has changed the file. You can choose **Reload File**, **Compare** or **Save Copy**.
- **YAML string values:** edited strings that resemble booleans, numbers, dates or comments are now quoted. Line endings and untouched front matter remain unchanged.
- **Template Preview links:** links on the preview's own `localhost` origin stay in the panel. External web links open in the system browser; other local ports and custom schemes are blocked.
- **Site creation:** new Blank and Starter sites are prepared in staging and moved into the selected folder only after every step succeeds. GitHub Pages `baseURL` edits now preserve TOML comments and unknown keys and create a snapshot.
- **FTP credentials and snapshots:** a tested password is saved only after the wizard is completed and remains attached to its deploy target. Removing a target, site or local settings keeps credentials and snapshots unless you choose the separate purge action.
- **Preflight build artifact:** local publishing now deploys the same isolated build that Preflight checked. The site's `public/` folder is left unchanged. GitHub Actions still builds remotely.
- **GitHub Pages strategy:** each target now uses either GitHub Actions or Built site branch. Existing Local Build + Full Project targets pause until a strategy is selected.
- **GitHub Actions status:** HugoKit now follows the workflow run matching the pushed commit, branch and managed workflow. If no matching run appears, the publish reports a timeout.
- **FTP sync manifests:** sync state is now tied to the protocol, host, port, username and remote root. Failed deletes are retried on the next publish; files already absent are treated as deleted.
- **Site selection during publishing:** an active publish now continues with the site and targets it started with, even if another site is selected.
- **Per-target cancellation:** parallel publish targets now keep separate process state, so cancelling one target does not replace or stop another target's processes.
- **External Hugo servers:** removing a site, resetting HugoKit or quitting the app no longer stops a server started elsewhere. **Stop** and **Restart** identify the external process and require confirmation.
- **GitHub token scope:** push and pull attach the token only to canonical `github.com` HTTPS URLs. Other hosts and redirects are rejected.
- **Git index locks:** HugoKit no longer deletes `.git/index.lock` or retries automatically. It leaves the active Git operation alone and stops with an explanation.
- **Protected file writes:** HugoKit resolves symlinks and rejects an operation if any destination is outside the site's root folder.
- **Preflight snapshot paths:** auto-fixes now use the full project-relative path for every previewed, snapshotted and changed file.
- **Preflight from the site menu:** **Preflight Check** is now available from the site's `⋯` menu.
- **Front matter during reordering:** Custom order preserves line endings, body text, comments, unknown fields and existing `weight` formatting. New TOML root weights are inserted before tables.
- **Content formats in Custom order:** the section scan now includes every built-in Hugo content format and nested section path before weights are changed.
- **Reordering controls:** drag from anywhere on a row or use the up and down buttons. The insertion line shows where the page will be placed.
- **Sort direction:** Date, Title and Custom order now share an ASC/DESC control. Undated pages remain at the bottom, and Custom order preserves the visible sequence after a rescan.
- **Large sections:** content scanning, sorting and batch writes have been updated for sections with hundreds of pages.
- **Content refreshes:** results from a cancelled scan or a previously selected site are now ignored.
- **Section landing pages:** Custom order no longer includes a section's `_index.*` page among its child rows or changes its `weight`.

## Fixed

- Switching sites during a publish no longer changes the active publish's project, destination or completion state.
- Cancelling a publish now stops its child processes, marks the target and run as cancelled, and sends no success or failure notification.
- Existing-server detection now treats project folder URLs with and without a trailing slash as the same path.
- Content scans no longer follow symlinks outside the content root.
- Auto-fixes for nested config and template files now preserve the full relative path when previewing, snapshotting and writing.
- Custom order no longer adds a second `weight` when the existing root key is quoted, duplicated or ambiguous.
- Custom order now accepts drops through the SwiftUI drag destination used by its visible row preview.
- Tags and categories can no longer be added twice with different letter casing.

## Notes

- **Requirements:** macOS 26 (Tahoe) or later
